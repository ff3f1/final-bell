# Final Bell — восстановление Windows-сборки

Сейчас в репозитории отсутствует исходный `project.godot`. Архив `Final Bell.zip` хранится на Google Drive, а подключение к Drive не может скачать его из-за лимита 256 МиБ. Этот порядок позволяет провести первичную диагностику **на компьютере владельца**, не передавая 665 МБ в чат и не добавляя экспорт в Git.

## 1. Сохранить оригинал и получить список файлов

На Windows установите Python 3.11+ (или воспользуйтесь существующим Python). Скачайте этот репозиторий с GitHub кнопкой **Code → Download ZIP** и распакуйте его. Откройте PowerShell в папке репозитория.

```powershell
python .\tools\inventory.py "C:\Путь\к\Final Bell.zip" --output "$env:USERPROFILE\Desktop\FinalBell_Audit"
```

Скрипт **не изменяет ZIP** и создаёт:

- `inventory.md` — краткий перечень исходников, экспортов, крупных файлов и рисков;
- `inventory.json` — полный список файлов, размеры, CRC32, SHA-256 всего ZIP.

**Отправьте `inventory.md` и `inventory.json` в следующий чат или добавьте их в отдельную рабочую папку.** Эти файлы обычно существенно меньше архива. Проверьте пути на наличие личной информации перед отправкой: отчёт содержит локальный путь к ZIP и имена файлов.

## 2. Если внутри есть `project.godot`

Это может быть исходный проект. **Не восстанавливайте его из PCK до проверки оригинальных файлов.** Распакуйте копию ZIP в отдельный каталог штатным архиватором, сохраните резервную копию. Проверьте скрипты/сцены/Blender-файлы, совместимость версии Godot и права на ассеты. Не открывайте неизвестные скрипты как доверенные автоматически.

## 3. Если внутри только `Final Bell.exe` и `Final Bell.pck`

Извлеките только экспортные файлы в новую папку (нужно свободное место):

```powershell
python .\tools\inventory.py "C:\Путь\к\Final Bell.zip" --output "$env:USERPROFILE\Desktop\FinalBell_Audit" --extract-packs
```

Экспорты появятся в `FinalBell_Audit\packs\...`, без перезаписи уже существующих файлов. Их SHA-256 попадёт в отчёт.

Затем используйте **[GDRETools](https://github.com/GDRETools/gdsdecomp/releases)** — инструмент восстановления проектов Godot:

1. Возьмите официальную Windows-версию из релизов проекта.
2. В GUI откройте **RE Tools → Recover project...** и укажите `.pck` (либо `.exe`, если ресурсы встроены внутрь него).
3. Сохраните результат **в новую пустую папку**, отдельно от оригинала. Сохраните журнал восстановления.
4. GDRETools определяет версию движка при восстановлении. Для редактирования используйте совместимую версию Godot, указанную в журнале, не выбирайте версию наугад.
5. Проверьте, что получили `project.godot`, сцены, скрипты и ассеты; посмотрите ошибки восстановления и импорта.

Для CLI, если у вас доступен исполняемый файл `GDRE_Tools.exe`:

```powershell
& "C:\Путь\к\GDRE_Tools.exe" --headless --recover="C:\Путь\к\Final Bell.pck"
```

Полный список параметров для вашей версии смотрите в её `--help` / README. Возможны неполные результаты (например, для шифрованных ресурсов, скриптов или отсутствующих исходных `.blend`). **Из PCK не гарантируется восстановление исходных моделей Blender или точного авторского кода.**

## 4. Следующий этап разработки

После восстановления подготовьте отдельную папку с редактируемым проектом. Загружайте в Git сцены, `.gd`, настройки и допустимые по размеру ассеты. **Не загружайте** сам `Final Bell.zip`, `.exe`, `.pck` в обычную историю Git. Для больших исходных ассетов оцените Git LFS; перед публикацией проверьте авторство и лицензии.

Далее: открыть восстановленный проект, проверить ошибки импорта и один полноценный бой; только после этого исправлять тайминги ударов, управление, hitbox/hurtbox и анимации. В `PROJECT_STATE.md` фиксировать только подтверждённые результаты.

## Проверка инструмента

```powershell
python -m unittest discover -s tests -v
```

Тесты создают искусственные ZIP в системной временной папке, не требуют исходной игры и не тестируют её игровой процесс.
